## 도화서 화원의 그림 — Phase 3 "그날의 나" 타임머신(What-if) UI

> 차트는 지나온 길을 보여주는 병풍입니다. 이번엔 그 병풍 앞에 관객이 손가락을
> 짚어 "그날 내가 여기 서 있었다면" 하고 물을 수 있게 합니다. 다만 병풍을
> 어루만지는 손짓(짧은 탭)과, 병풍의 결을 오래 들여다보는 손짓(오래 누르는
> 크로스헤어)이 같은 손이 하는 두 가지 다른 일임을 분명히 갈라 그려야
> 서로의 발을 밟지 않습니다.

### 0. 읽은 자료

- `web/src/pages/StockDetailPage.tsx` (섹션 순서, `detail-grid` 구조, 탭 상태)
- `web/src/components/CandleChart.tsx` (tf 목록, `isMinuteTf`/`isLiveCapableTf`, 툴바·범례 구조, UP/DOWN 색 상수)
- `web/src/components/PullbackCard.tsx` (6종 상태칩 색 매핑, 체크리스트 문법)
- `web/src/components/DecisionGauge.tsx` (판정 라벨 색 매핑, `insufficient` 처리 패턴)
- `web/src/components/SignalChip.tsx` (5단계 시맨틱 컬러, `데이터부족` 아웃라인 폴백)
- `web/src/index.css` (디자인 토큰 전체, `.panel`/`.pullback-card`/`.candle-chart` 카드 문법, 등락 색, `.banner--warning`)
- `docs/wireframes/phase2v2-live-ui.md` (이 레포의 와이어프레임 서술 관행 — 원칙→상태표→화면→변경지점표→사유 순서)

### 1. 불변 원칙

1. **새 색을 만들지 않는다.** 이 화면의 모든 색은 기존 토큰에서 그대로 가져옵니다(§11-1 색상 출처 표로 증명).
2. **확정 판정의 위계를 침해하지 않는다.** "그날 봇 판정"은 *과거 시점*의 회고적 참고 정보입니다. 현재 상세 페이지의 `DecisionGauge`(오늘의 확정 판정)와 시각적으로 경합해선 안 되므로, 이 기능은 전용 카드 안에 격리하고 게이지 근처에 배치하지 않습니다(§3 배치 참조).
3. **과장 문구 배제.** "대박", "인생역전" 류 표현 금지. 서사는 사실 서술("그때 ○○원으로 샀다면")에 그치고, 결과는 숫자와 색으로만 강조합니다.
4. **모의 계산임을 숨기지 않는다.** 결과 카드 하단 고지는 어떤 상태(성공/에러)에서도 생략되지 않습니다.
5. **등락 색상 관행 통일.** 이 문서 전체에서 "이익·상승"은 적색(`#b91c1c` 계열), "손실·하락"은 청색(`#1d4ed8` 계열) — 기존 `price-section__change`/`stock-card__change`와 동일.

### 2. 데이터 계약 메모 (화면 설계 전제)

```
GET /api/stocks/{code}/whatif?date=&amount=
→ {
    buy_date, buy_price, shares, current_price, eval_amount, profit, return_pct, multiple,
    kospi { 동일 구조 },
    bot_judgment { long_view, macd_1d, rsi_1d, pullback_status, note },
    error
  }
```

- `error`가 채워지면 나머지 필드는 신뢰하지 않고 **에러 상태**로 그린다(§6-3). 백엔드가 이미 한글 안내문을 내려준다는 전제(기존 API의 `SignalView`/`PullbackStatus` 관행과 동일하게) 하에 `error` 원문을 그대로 노출한다 — 프론트가 자체 에러 코드 매핑표를 만들 필요가 없도록 이 전제만 backend-gigwan과 짧게 확인 권고.
- `bot_judgment.long_view`는 기존 `SignalChip`이 다루는 5단계 값(또는 `데이터부족`)과 동일 타입으로 가정 — 다르면 `SignalChip`의 `resolveStyle` 폴백이 그대로 안전망 역할을 한다.
- `bot_judgment.pullback_status`는 기존 `PullbackStatus` 6종과 동일 타입으로 가정 — `PullbackCard.STATUS_COLOR` 매핑을 그대로 재사용(값 export 또는 동일 상수 복제는 implementer 판단).
- **재무 지표 미포함 고지**: 오늘의 "장기" 판정은 기술 지표+재무를 함께 본다(`StockDetailPage`의 `long_view`). 그러나 과거 특정일 회고 판정은 그 시점 재무 스냅샷을 재구성하지 않는 한 기술 지표(MACD/RSI/눌림목)만의 결과일 가능성이 높다. 사용자가 "왜 오늘 판정이랑 계산법이 다르지?"라고 오인하지 않도록, 결과 카드에 **"당시 기술적 지표 기준 판정(재무 데이터 미반영)"** 캡션을 고정 노출한다(§6-1).

### 3. 화면 배치 — StockDetailPage 안에서

새 섹션은 12열 Bento 그리드(`detail-grid`) *밖*, 전체 폭 독립 카드로 차트 카드 다음, 푸터 앞에 놓습니다. 게이지 카드와 물리적으로 떨어뜨려 "오늘의 확정 판정"과 "과거 회고 판정"이 한 화면에서 뒤섞이지 않게 합니다.

```
[detail-header]
[price-section]
[analysis-toggle-wrap]
┌ detail-grid (기존, 무변경) ─────────────────────┐
│ gauge │ factors(+pullback) │ bollinger │ chart │
└──────────────────────────────────────────────────┘
┌ timemachine-card (신규, 전체 폭) ──────────────────┐   ← 본 문서의 화면 1
└────────────────────────────────────────────────────┘
[app-footer]
```

#### 4-2. 로딩 상태


#### 4-3. 성공 — 결과가 폼 아래에 이어 붙음

```
│ ┌──────────────────────────────────────────┐   │
│ │                계산하기                    │   │  ← 폼은 그대로 남음(재계산 용이)
│ └──────────────────────────────────────────┘   │
│ ──────────────────────────────────────────── │
│           (결과 카드 — §6 참조)                │
└──────────────────────────────────────────────────┘
```

**설계 결정 — 왜 폼을 안 숨기는가**: 인라인 섹션은 페이지 스크롤 여유가 충분한 맥락입니다. 날짜를 바꿔가며 여러 번 비교해보는 "놀이"가 이 기능의 핵심 재미이므로, 폼을 접지 않고 결과를 아래에 이어 붙여 재계산 왕복을 짧게 만듭니다(재계산 시 결과 영역만 갱신, 폼은 값 유지).

### 7. 인터랙션 명세 — 탭 vs 롱프레스 vs 드래그 제스처 충돌 해결

CandleChart 캔버스 위에서 하나의 손가락이 낼 수 있는 제스처는 세 갈래로 갈립니다. 아래 규칙은 **시간(ms)과 이동거리(px) 두 축**으로만 판별해 애매함을 없앱니다.

| 제스처 | 판별 조건 | 동작 |
|---|---|---|
| **탭(짧게)** | pointerdown → pointerup, 경과 ≤ 400ms **그리고** 이동거리 < 8px, 그 사이 롱프레스 타이머 미발화 | 지원 tf(§7-1)면 해당 봉의 날짜로 바텀시트 오픈. 미지원 tf면 하단 §7-2 토스트 |
| **롱프레스(오래 누름)** | pointerdown 유지 ≥ 450ms, 그 사이 이동거리 < 8px | 크로스헤어 스크럽 모드 진입(기존 데스크톱 호버와 동등한 OHLC 참조를 터치에서 재현) — 진입 시 짧은 시각 피드백(크로스헤어 라인 표시) 권장. **해제 시(pointerup) 탭으로 간주하지 않음** — 이미 400ms 임계를 넘겼으므로 바텀시트를 열지 않는다 |
| **드래그(이동)** | 450ms 타이머가 발화하기 *전에* 이동거리가 8px를 초과 | 기존 차트 팬/줌 그대로(lightweight-charts 기본 동작) — 탭도 롱프레스도 취소 |

```
pointerdown
   │
   ├─ 8px 넘게 움직임(450ms 전) ──────────────→ [드래그] 팬/줌, 이후 무시
   │
   ├─ 450ms 경과, 이동 <8px 유지 ─────────────→ [롱프레스] 크로스헤어 스크럽 진입
   │                                              └─ pointerup → 스크럽 종료(시트 안 열림)
   │
   └─ 400ms 이내 pointerup, 이동 <8px ────────→ [탭] 바텀시트 오픈(지원 tf일 때)
```

#### 7-1. 탭 지원 범위 — 어떤 타임프레임에서 여는가

- **지원**: `1m·5m·15m·30m·60m·120m·240m·1d` — 이 봉들은 각각 하루 이내(또는 하루 그 자체)의 시각을 갖고 있어, 봉의 타임스탬프에서 "시:분"을 버리고 "날짜"만 뽑으면 모호함이 없습니다.
- **미지원**: `1w·1M·1y` — 한 봉이 여러 날을 품고 있어 "그 봉의 날짜"가 무엇인지 자체가 모호합니다(주봉이면 그 주의 시작일? 마지막 거래일?). 사용자가 화면에서 보는 봉과 실제 프리필될 날짜가 어긋나 보일 위험이 커 이번 범위에서는 지원하지 않습니다.
- 미지원 tf에서 탭이 들어오면: 조용히 무시하지 않고, 짧은 스낵바(토스트) "이 주기에서는 지원하지 않아요 — 일봉 이하에서 사용해주세요"를 약 2초 노출(캔들 차트 하단, `candle-chart__overlay`류 오버레이와 겹치지 않는 위치, 클릭 불가·자동 소멸).
- 지원 tf일 때만 §5-1의 힌트 캡션("🕰 봉을 탭하면…")을 노출 — 미지원 tf에서는 힌트 자체를 숨겨 "여기선 안 되는구나"를 굳이 알려주지 않고 자연히 사라지게 한다.

#### 7-2. 프리필 규칙

- 날짜: 탭한 봉의 타임스탬프에서 날짜만 추출(시:분 버림).
- 금액: 이번 세션에서 마지막으로 계산에 쓴 금액이 있으면 그 값, 없으면 기본값 1,000,000원.
- 시트가 열리는 즉시 계산이 자동 실행되지는 않는다 — 사용자가 값 확인 후 "계산하기"를 직접 눌러야 요청이 나간다(의도치 않은 API 호출 방지, 금액을 조정할 여지 제공).

#### 7-3. 접근성 대체 경로

터치 제스처는 스크린리더·키보드 사용자에게 그대로 작동하지 않습니다. 캔들 차트 영역과 별개로, **화면 1의 인라인 섹션은 항상 날짜를 직접 타이핑/키보드로 입력할 수 있는 유일하고 완전한 대체 경로**입니다 — 차트 탭 진입(화면 2)은 어디까지나 단축 경로이지 유일한 진입점이 아님을 구현 시 지켜주십시오.

#### 11-2. 왜 게이지 근처에 배치하지 않는가

오늘의 확정 판정(`DecisionGauge`)은 이 앱에서 가장 신뢰받아야 할 단일 결론입니다. "그날 봇 판정"은 과거 시점의 회고이자 참고 정보일 뿐인데, 게이지 옆에 놓이면 두 판정이 시각적으로 나란히 경합해 사용자가 "지금 판정이 바뀐 건가?"라고 오인할 위험이 있습니다. 그래서 전용 카드로 완전히 분리하고, 물리적으로도 차트 다음(게이지에서 가장 먼 위치)에 둡니다.

#### 11-3. 왜 병치 바(비교 바)를 막대 길이로 표현하는가

"내가 이 종목 대신 코스피를 샀더라면"이라는 비교는 숫자만으로는 즉각 와닿지 않습니다. 같은 원금 기준으로 최종 배수를 막대 길이로 나란히 놓으면, 숫자를 읽기 전에 "어느 쪽이 더 길다"가 먼저 눈에 들어와 비교의 재미와 명확성을 동시에 얻습니다 — 이것이 이 기능의 "바이럴 공식" 핵심입니다.

#### 11-4. 왜 "재무 데이터 미반영" 고지를 고정 노출하는가

오늘의 "장기" 탭 판정은 기술 지표와 재무 요인을 함께 봅니다. 과거 특정일의 회고 판정(`bot_judgment`)이 기술 지표만으로 산출된다면, 사용자가 두 판정 방식을 같은 것으로 오해하고 신뢰도를 잘못 매길 수 있습니다. 이 한 줄은 과장을 막는 동시에 "왜 판정 근거가 다르지"라는 혼란을 사전에 차단합니다.

#### 11-5. 왜 탭/롱프레스를 시간+거리 두 축으로 가르는가

한 손가락으로 세 가지 다른 의도(짚기·오래 보기·훑기)를 구분하는 유일하게 신뢰할 수 있는 신호는 "얼마나 오래, 얼마나 움직였나"뿐입니다. 어느 한 축만 쓰면(예: 시간만) 손이 떨려 8px쯤 움직인 사용자가 탭을 의도했는데도 드래그로 오판되는 사고가 잦습니다. 두 축을 함께 쓰면 오판을 크게 줄일 수 있습니다.

### 12. 접근성·반응형

- **키보드 네비게이션**: 화면 1의 폼은 완전한 키보드 대체 경로입니다(날짜 `<input type="date">`, 금액 입력, 프리셋 버튼, CTA 모두 tab 순회 가능, 기존 전역 `:focus-visible` 스타일 그대로 적용). 프리셋 칩은 `<button>`으로 구현해 Enter/Space로 활성화.
- **바텀시트 모달 규칙**: `role="dialog" aria-modal="true" aria-labelledby="{헤더 id}"`, 열릴 때 첫 포커스는 날짜 입력(프리필된 값 확인이 우선), `Escape` 키·백드롭 클릭·닫기 버튼 모두 동일하게 닫음, 닫힐 때 포커스는 시트를 연 트리거(차트 봉 또는 등가 버튼)로 복귀.
- **결과 완료 알림**: 로딩→성공/에러 전환 시 화면이 크게 바뀌므로, 스크린리더 사용자에게 완료를 알리는 짧은 `aria-live="polite"` 안내(예: "계산 완료" / "오류: {메시지}")를 별도 `sr-only` 요소로 한 번만 흘려보낸다 — 결과 카드 본문 전체를 `aria-live`로 감싸면 값이 안 바뀌어도 반복 낭독되어 피로가 생기므로 지양(기존 `candle-chart__overlay`의 `role="status"` 관행과 같은 절제 원칙).
- **모션 최소화**: 로딩 스피너는 기존 `.candle-chart__spinner`/`prefers-reduced-motion` 처리를 그대로 재사용 — 신규 애니메이션을 만들지 않는다.
- **모바일(≤640px)**: 인라인 카드는 폭 100%, 프리셋 칩은 `flex-wrap`으로 필요 시 2줄. 바텀시트는 `max-height: 85vh`, 내부 스크롤, iOS 하단 안전영역(`safe-area-inset-bottom`) 패딩 확보.
- **데스크톱(≥1024px, 보조 고려)**: 인라인 섹션은 폼(좌)과 결과(우)를 2열로 나란히 배치해도 무방 — 다만 이는 여유 시 개선 사항이며 1차 구현 필수 요건은 아님. 바텀시트는 모바일 전용 패턴을 유지하고, 넓은 화면에서 차트 탭 진입 시에는 같은 `BottomSheet` 컴포넌트를 화면 중앙 모달 형태로 여는 정도의 경미한 변형을 고려할 수 있음(필수 아님, 시간 되면).

### 13. 사용자 흐름 요약

```
[상세 페이지 진입]
   → 차트 아래 "그날의 나" 카드 상시 노출(화면1, idle)
   → (경로 A) 폼에 직접 날짜·금액 입력 → 계산하기
   → (경로 B) 차트에서 과거 봉 짧게 탭(지원 tf) → 바텀시트 프리필(화면2)
        → 시트 안에서 금액 조정 가능 → 계산하기
   → 계산 중(로딩, 폼 disabled)
   → 성공: 결과 카드(화면3) — 배수·수익률·비교 바·봇 판정·공유·고지
        └ 경로 A: 결과가 폼 아래 이어 붙음, 폼 값 유지 → 재계산 반복 가능
        └ 경로 B: 시트 내용이 결과로 전환, "‹ 다시 계산하기"로 폼 복귀 가능
   → 실패: 에러 카드(원문 또는 fallback) + 재시도 버튼 → 폼으로 복귀
   → 공유하기 → OS 공유 시트(또는 클립보드 복사 폴백)
```
